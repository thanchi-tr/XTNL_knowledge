# M1 Today: one clock, one streak, capture and graded todos

The app opens on /today. Any task can be captured in one line from any page or from the phone's home screen. Every row shows exactly what it pays, and a tick pays exactly that, with a receipt. The daily streak counts reviews, ideas and tasks rather than Idea.updatedAt. Every day edge in the app is 04:00 local. Migration 1 (life_core) ships here.

## One clock: life-day.ts and the knowledge cut-over

**Spec.** src/lib/life-day.ts is pure, has no dependencies and is client-importable.
- LIFE_TZ = process.env.NEXT_PUBLIC_USER_TIMEZONE || 'Australia/Brisbane'. It is inlined at build time, so the server and browser bundles agree. It must never be a server-only env var and never throws.
- DAY_START_HOUR = 4.

API (every function also takes an optional tz argument for tests):
- dayKeyOf(instant) returns 'YYYY-MM-DD', the local date of (instant − 4 h), via Intl.DateTimeFormat('en-CA', {timeZone, hourCycle:'h23'}).formatToParts.
- zonedToInstant(y, m, d, h) uses a two-pass offset search.
- dayStartOf(key) is 04:00 local. dayEndOf(key) = dayStartOf(addDays(key, 1)).
- todayKey(now), addDays, daysBetween, weekdayOf (Mon = 1).
- weekStartOf(now) is Monday 04:00 local. weekKeyOf(key) returns '2026-W41'.
- dateColumn(key) is a UTC-midnight Date for @db.Date columns; keyOfDateColumn is its inverse.

Cut-over, in one commit:
- due.ts:
  - dueCutoff(now) = dayEndOf(dayKeyOf(now)) − 1 ms.
  - daysUntilDue compares day keys.
  - Rewrite the module comment.
- mastery.ts: utcDayStart → dayStartOf(dayKeyOf(now)). This covers the attestation once-per-day limit and decay's 'already_today'.
- field-streaks.ts:
  - truncateToUtcMidnight → dateColumn(dayKeyOf(now)).
  - One-release shim: a gap of 2 counts as continued when lastActiveDay < CUTOVER_DAY, so the switch can neither break a streak nor trigger DOUBT.
  - Move streakBonusPercent and STREAK_BONUS_CAP_PERCENT to a new pure src/lib/streak-curve.ts and re-export them. field-streaks imports prisma, so the browser cannot import it.
- daily-focus.ts: utcDayKey → dayKeyOf.

## Task engine: templates, recurrence, lazy instances, basic goals

**Spec.** src/lib/recurrence.ts (pure):
- Grammar: DAILY | WEEKDAYS | DOW:1,4 | EVERY:N (fixed phase from startDay) | AFTER:N (next = last done + N; never allowed as compulsory) | TARGET:N/W | TARGET:N/M (distinct days per life week or month) | MONTHLY:D (31 clamps to the month's last day).
- ONCE uses dueDay with dueKind PLANNED (carries forward silently, never late) or DEADLINE (late after that day).
- Undated ONCE tasks are Anytime, or Inbox when inbox = true.
- occursOn(t, key, lastDoneKey), nextDue, periodProgress, describeRule ('Mon · Thu').

src/lib/habit.ts (pure, derived on read, no counters):
- perDutyStreak from expected occurrences versus instances. DONE counts; EXCUSED, SKIPPED and MVV hold; a past occurrence outside the record window with no instance breaks it.
- habitStrength is the Loop EWMA, a = 0.052: kept S = S·0.948 + 0.052; missed S·0.948; held unchanged.
- Rungs: Seeded < 0.25, Forming < 0.60, Established < 0.90, Automatic ≥ 0.90.
- keptToNextRung = ceil(ln((1−target)/(1−S)) / ln(0.948)).

src/lib/tasks.ts:
- createTemplateCore: one INSERT with the lexical grade and a lazily upserted LifeSettings.
- completeInstanceCore(templateId, {day ∈ today|yesterday, slot, minutes?, mvv?}):
  - One read wave, then one $transaction array: instance upsert on (templateId, day, slot), the TASK event (dedupe 'task:<tpl>:<day>:<slot>:<attempt>'), and template updateMany setting gradeFrozenAt when null and completedAt for one-offs.
  - P2002 returns the stored receipt, so a double tap is idempotent. There is no interactive transaction.
- undo: within 10 min on the same life day. Writes an UNDO event (xp −paid, rawXp −raw, dedupe 'undo:<eventId>') and sets the instance to UNDONE; re-completing reuses the row.
- skip: non-compulsory only; SKIPPED, 0 XP, the streak is held.
- again: slot + 1.
- reschedule and archive: templates with history are archived, never deleted.

Goals (basic):
- kind GOAL with horizon from the tag or from the deadline distance: ≤ 30 days SHORT, ≤ 180 days MID, else LONG. The horizon can be lowered but never raised.
- Children link through parentId ('^name').
- krMetric CHILDREN (share of ONCE children done; recurring children shown as 'support habits 82% kept (28 d)') or MANUAL ('+1', a GOAL_PROGRESS event with qty).
- No payout until M5.

src/app/actions/tasks.ts ('use server', async exports only, {ok:true,value}|{ok:false,error}): createTask, completeTask, undoCompletion, undoCapture (archive within 10 min when there are 0 instances), skipTask, againTask, rescheduleTask, archiveTask, clarifyInbox, goalProgress. They call refresh() from next/cache when the caller is /today (Server Actions only, per 04-functions/refresh.md).

Expected instances are never pre-created.

## Quick capture: one line, live chips, undoable

**Spec.** src/lib/capture-parse.ts is pure and shared by client and server. The server re-parses the raw text as the authority, using the client's list of reverted spans.

Tokens:
- Mode prefixes:
  - 'idea:' or 'i:' → an IDEA_DRAFT inbox item opening /add?draft=<id>; M3 upgrades this.
  - 'x ', 'did ' or 'done ' → done now.
  - 'goal:', 'goal mid:'.
- '!' or 'must' → compulsory. It requires a fixed schedule or a deadline; otherwise the chip warns 'Compulsory needs a fixed schedule or a deadline'.
- A trailing '?' → Inbox.
- Duration: '~30m', '30m', '45 min', '1h', '1h30', '1.5h', '90min'.
- Recurrence:
  - daily, every day, weekdays, weekends, 'every mon,thu', 'every other day', 'every 2 weeks', weekly, monthly, 'every 15th', 'monthly on 15';
  - 'every! 3 days' or '3 days after' → AFTER;
  - '3x/week', '3x a week', '3/wk', 'twice a month' → TARGET.
- Dates:
  - today, tonight, tomorrow, tmr, weekday names (the next one; today's own name means today), 'next week', 'in 3 days', '15 oct', 'oct 15', '15/10' (D/M), eom → PLANNED;
  - 'by <date>' → DEADLINE;
  - weak words (may, sat, sun, mar, march) count only after on, by or every;
  - times like '7pm' are kept in the title.
- Tags: #body #duty #craft #care, #short #mid #long, #play.
- '^name' → parent goal, by best Dice match among open goals.
- '(min: 10 pushups)' or 'min: …' → MVV.
- Study links: 'review 20', 'review due', 'add 3 ideas' → autoMetric.
- Output: {title, mode, kind, recurrence, dueDay, dueKind, estMinutes, compulsory, horizon, track, intrinsic, mvv, autoMetric, doneNow, tokens[{id, start, end, field, label}]}.
