# M3 Capture everywhere and one-box ideas

Capture needs zero required fields from every surface the user has:
- Android's share sheet;
- a token-protected API for Tasker, HTTP Shortcuts and similar tools;
- a system-wide Win+Shift+Q on the desktop;
- an idea box that files a real Idea automatically and cannot lose the text when Gemini fails.
No migration.

## Android share target

**Spec.** manifest.ts share_target: {action: '/capture/share', method: 'POST', enctype: 'application/x-www-form-urlencoded', params: {title: 'title', text: 'text', url: 'url'}}. This is supported by Next's Manifest type (manifest-types.d.ts share_target).

src/app/capture/share/route.ts (POST, force-dynamic):
1. Reject with 403 when Sec-Fetch-Site is 'cross-site'. 'same-origin', 'none' and a missing header are allowed. The app has no auth, and a Route Handler gets no Server Action origin check.
2. Read the body with request.formData().
3. title = the shared title, or the first line of text cut to 140 chars. note = the rest of the text plus the url.
4. captureCore(inbox: true, captureSource: 'share'): one INSERT with a lexical grade, then after() AI sizing.
5. Return 303 to /today?captured=<id>. That URL opens the InboxSheet with the item highlighted and an Undo.

The README documents the TWA rebuild (android-browser-helper ≥ 2.0.1).

**Files.** src/app/manifest.ts, new src/app/capture/share/route.ts, src/lib/capture-core.ts (shared by action, share route and API; extracted from actions/capture.ts), src/components/today/InboxSheet.tsx (?captured highlight), README.md

**Tests.** scripts/capture-parse-check.ts, share section:
- the title/note split: a URL-only share, text with an embedded URL, and a 300-char text;
- the Sec-Fetch-Site decision table as a pure function.

Manual on the phone after the APK rebuild: share from Chrome lands in the Inbox in 2 taps.

## Token capture API and a system-wide desktop hotkey

**Spec.** src/app/api/capture/route.ts (POST, force-dynamic):
- Authorization: Bearer CAPTURE_TOKEN, compared with crypto.timingSafeEqual.
- Fails closed: 503 when CAPTURE_TOKEN is unset, 401 when the token is wrong. Tokens are never accepted in a URL.
- Body {text, inbox?}, ≤ 8 KB. Returns {ok, id, title, tokens}.
- Limited to 60 requests per hour per instance (in-memory).

README recipes:
1. An AutoHotkey v2 script for Win+Shift+Q:
   - InputBox, then WinHttp.WinHttpRequest.5.1 POST with the token read from %APPDATA%\xtnl\capture-token.txt (never inside the script), with a small JSON escape.
   - TrayTip shows 'Captured' or the status.
   - A shortcut in shell:startup runs it at login.
2. Android 'HTTP Shortcuts' or Tasker: an HTTP POST with the same header, for voice or home-screen widgets.

**Files.** new src/app/api/capture/route.ts, README.md (AutoHotkey + HTTP Shortcuts recipes); .env / Vercel: CAPTURE_TOKEN

**Tests.** A pure check covering:
- the token comparison, including unequal lengths;
- the 503 / 401 / 413 decision table;
- the rate limiter's window arithmetic;
- JSON escaping in the documented snippet, checked by running its escape function as JS in the check script.

## One-box idea capture that cannot be lost

**Spec.** In the capture sheet's Idea mode, 'idea: <prompt> :: <answer>' or a second line holds the answer. The capture:
1. Writes an IDEA_DRAFT template first, in one INSERT (title = prompt, note = answer, inbox true).
2. In after(), calls submitIdea with no fieldId (automatic Field routing, ideas.ts:36-42), type SHORT and collectionLabel BOOK.
3. created: the draft is archived and the existing IDEA_CREATE hook records the pay.
4. saturated: the draft stays, with the note 'Looks like <matched title>' and a link to /add?draft=<id> for Link or Enrich.
5. merged: the draft is archived with a note.
6. Any throw, such as an embedding outage: the draft stays in the Inbox as 'Idea to file' with the error.

With no answer, the item stays a draft that opens /add?draft=<id>.

submitIdea fallbacks, so an outage no longer throws:
- dedup.ts:282 synthesizeNodeData failure → null node data. The columns are nullable.
- domain-discovery.ts:128 nameNewDomain failure → a name from the first tag or the first three content words in Title Case, reusing the existing case-insensitive match.

AddIdeaForm.handleSubmit gains a catch that keeps the text and shows the error.

**Files.** src/app/actions/capture.ts (captureIdea), src/lib/dedup.ts, src/lib/domain-discovery.ts, src/components/AddIdeaForm.tsx, src/app/add/page.tsx

**Tests.** scripts/capture-parse-check.ts: 'idea: Q :: A' and two-line forms.

A pure check of fallbackDomainName: tags first, then words; stop-words removed; ≤ 40 chars.

Planner ordering fixture: the draft is written before any model call.

The fallback wrapper is tested with a stubbed rejected promise, never a live failed submission.
