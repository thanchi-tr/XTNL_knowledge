# M4 Body: Health Connect sync, Samsung backfill and effort-priced workouts

Workouts, steps and heart rate from Samsung Health arrive on their own through Health Connect, deduplicated across every source. Each workout is priced by effort (one session, one payment) and asks for one optional RPE tap. Exercise tasks tick themselves, and years of history backfill the gauges without paying XP. Migration 3 (life_body) ships here.

## Health ingest endpoint with cross-source dedupe

**Spec.** POST /api/ingest/health (force-dynamic, no maxDuration export).

Auth:
- Authorization: Bearer HEALTH_INGEST_TOKEN or x-api-key, compared with timingSafeEqual.
- 503 when the token is unset; 401 when it is wrong.
- The body is read as text: 413 over 4 MB.
- ?dryRun=1 or X-Dry-Run: 1 returns the plan and writes nothing.

Format detection:
1. HC Webhook (verified docs): root {timestamp, app_version, ...}.
   - 'exercise' [{type, start_time, end_time, duration_seconds, distance_meters?, steps?, avg_cadence_spm?, ...}]
   - 'steps' [{count, start_time, end_time}]
   - 'heart_rate' samples {bpm, time}, or aggregates {time, avg, min, max}, detected by 'avg'
   - There are no ids, and it resends a rolling 48 h window, so natural keys are used. Parse leniently and ignore unknown keys; the app ships often.
2. Generic v1, the stable documented contract: {source:'generic', workouts:[{id?, type, start, end, distance_m?, kcal?, avg_hr?, max_hr?, rpe?}], steps:[{start, end, count} | {date, count}], heart_rate:[{time, bpm} | {time, avg, min, max}]}.
3. Tasker + TaskerHealthConnect: {source:'tasker', records:[raw ExerciseSessionRecord | StepsRecord | HeartRateRecord JSON]}, using metadata.id as externalKey.
4. Anything else: 422 listing the accepted shapes.

Pipeline (src/lib/health-ingest.ts):
- Normalise and validate: duration 1 min to 10 h; start > now + 10 min is rejected.
- day = dayKeyOf(start). historical = day < epochDay, or start more than 14 days before ingest.
- Workout createMany skipDuplicates on (userId, source, externalKey).
- Cross-source match, with one query over the batch window ±12 h. A duplicate is the same family (or either OTHER) with either (|Δstart| ≤ 5 min and |Δduration| ≤ 20%) or overlap ≥ 60% of the shorter session. The first row stays canonical (paid). The newcomer gets canonicalId and fills the canonical's empty fields, with precedence SAMSUNG_EXPORT > TASKER > HC_WEBHOOK > GENERIC > MANUAL. A sensor row matching a MANUAL canonical overwrites its timing and HR and keeps the manual RPE. Any repricing is an ADJUST row (MERGE) within 48 h.
- HR is upserted into HrBucket per minute (source, minute). It fills avgHr and maxHr for sessions covered ≥ 50%. Late HR re-grades within 48 h (ADJUST HR_LATE).
- Steps are upserted into StepInterval by (source, start, end). Day total = max(the max-per-minute sweep over fine intervals spread evenly, the largest coarse daily total). Intervals over 6 h are coarse and attributed to their midpoint's day. The daily total is clamped to 100,000.
- New canonical, non-historical sessions: priceWorkout → WORKOUT event ('workout:<id>', countsForStreak when ≥ 10 min). Then EXERCISE-task auto-complete and PR detection.
- The response is always 200 for partially valid batches, so the bridge's watermark advances: {ok, format, workouts:{accepted, duplicate, merged, historical, rejected}, steps:{upserted}, hr:{upserted}}.
- Every real request writes an IngestLog row and invalidates 'life' and 'activity'.

**Files.** prisma/schema.prisma + prisma/migrations/20261109000000_life_body/migration.sql; new src/app/api/ingest/health/route.ts, src/lib/health-ingest.ts (adapters, matcher, steps sweep, writer); edit src/app/api/cron/life/route.ts (HrBucket purge > 14 d); .env / Vercel: HEALTH_INGEST_TOKEN

## Workout price, RPE prompt and one session, one payment

**Spec.** Implements grading section D in src/lib/body-grade.ts (pure): intensity, load, the guard, the day curve, MEM, CTL/ATL and PR detection. It shares the knee with life-grade.ts. Formula version 'life-2'.

RPE rating:
- A 'Rate it' chip (1-10 with CR-10 anchors: '3 moderate', '5 hard', '7 very hard', '10 maximal') appears on /today and /train from 30 min after a session ends until 48 h after.
- rateWorkout writes ADJUST (RPE_RATED) with delta = new − old. The RPE is capped by HR evidence.

Manual logs:
- 'x run 30m rpe7' or the Log workout sheet creates a MANUAL workout (≤ 180 min for pay).

EXERCISE-category tasks:
- A canonical session on the same day in the task's family (or any family when autoFamily is null or OTHER), lasting ≥ 50% of the estimate, auto-completes the task: instance DONE, source auto:workout, TASK event xp 0 'paid by workout'.
- A manual tick on an EXERCISE task creates a MANUAL workout (start = now − estimate) priced by the workout formula. A later sensor session merges into it, and the difference is an ADJUST.
- A sensor session arriving after a MISSED compulsory exercise occurrence was judged proves it was done on time: DEBT_REPAID in full, the instance set to DONE at T 1.00, and the streak restored.

## Samsung Health export backfill

**Spec.** /train/import is a client component, because the Server Action body limit is 1 MB (docs 02-guides/server-actions.md:83). Accepted input:
- multi-selected CSVs, which is the phone path;
- a .zip, unzipped with fflate unzipSync with a filter so only matching entries are inflated (the phone's My Files can compress the folder);
- a folder via webkitdirectory, desktop only.

Files are matched anywhere in the archive:
- /com\.samsung\.shealth\.exercise\.\d+\.csv$/
- /com\.samsung\.shealth\.tracker\.pedometer_day_summary\.\d+\.csv$/ and step_daily_trend

src/lib/samsung-csv.ts (pure):
- Row 0 is metadata; row 1 is the header. The 'com.samsung.health.exercise.' prefix is stripped and columns are matched by suffix.
- Trailing extra columns are truncated. Parsing is RFC 4180, quote-aware.
- Columns read: start_time and end_time ('YYYY-MM-DD HH:mm:ss.SSS' in UTC, with time_offset 'UTC+1000'), duration (ms), exercise_type, distance, calorie, mean_heart_rate and max_heart_rate (0 means null), datauuid.
- day = dayKeyOf(start).

Flow:
- A preview comes first: counts per kind, the date range, historical versus payable rows, and unmapped codes.
- importSamsungChunk (Server Action) receives ≤ 300 normalised rows per call, sequentially, and runs them through the same health-ingest writer and matcher. Source is SAMSUNG_EXPORT; externalKey is datauuid or the natural key. The import is resumable.
- Rows older than 14 days are historical: 0 XP, but they count as baselines and for gauges and the guard.
- One IngestLog row per chunk. Summary card: 'Imported 1,248 sessions · 37 duplicates · 3 skipped'.

**Files.** package.json (fflate); new src/lib/samsung-csv.ts, src/app/train/import/page.tsx, src/components/train/SamsungImport.tsx; src/app/actions/tasks.ts (importSamsungChunk)
